功能

直接管理你現有的 CI 系統。

01

檢視執行狀態

查看 repositories、pipelines、build logs、agents 與系統狀態。

02

執行操作

透過支援的讀取與寫入操作管理 Woodpecker CI 資源，包括 secrets。

03

保持本機執行

MCP server 在你的電腦執行，連接你設定的 Woodpecker API。

開始使用

連接你的 MCP 主機。

需要 Bun 1.1 以上版本，以及結尾為 /api 的 Woodpecker API 網址。

C

Codex App

從 GitHub repository 安裝 plugin。

git clone https://github.com/jurislm/woodpecker-ci-plugin.git
cd woodpecker-ci-plugin
codex plugin marketplace add .
codex plugin add woodpecker-ci@woodpecker-ci-marketplace

在 MCP server process 環境設定 WOODPECKER_URL 和 WOODPECKER_API_TOKEN。

↗

Cursor

從 GitHub 匯入 plugin。

  1. 開啟 Customize → Add Marketplace → Import from GitHub。
  2. 輸入 jurislm/woodpecker-ci-plugin，新增 Woodpecker CI Plugin。
  3. 在 plugin 設定中填入 Woodpecker 網址和 token。
前往 GitHub repository ↗
直接設定 MCP server

其他 MCP 主機可用 Bunx 執行已發布的套件，並在主機的安全環境設定中提供憑證。

{
  "mcpServers": {
    "woodpecker-ci": {
      "command": "bunx",
      "args": ["-y", "@jurislm/woodpecker-ci-plugin@latest"],
      "env": {
        "WOODPECKER_URL": "https://ci.example.com/api",
        "WOODPECKER_API_TOKEN": "..."
      }
    }
  }
}

安全與限制

Token 留在 MCP 主機環境。

伺服器以 bearer authentication 傳送 token。Token 不會出現在 logs 或 tool metadata，secrets 值也會從 tool results 移除。憑證只放在 MCP 主機環境，切勿提交到 repository。

  • 01 不提供 hosted /mcp endpoint
  • 02 不提供 OAuth 流程
  • 03 不讀取 DRONE_TOKEN
