Work with the CI system you already run.

01

Inspect CI activity

Browse repositories, pipelines, build logs, agents, and system state.

02

Manage resources

Use supported read and write operations for Woodpecker CI resources, including secrets.

03

Run it locally

The MCP server runs on your machine and connects to the Woodpecker API you configure.

GET STARTED

Connect your MCP host.

Use Bun 1.1 or newer and a Woodpecker API URL ending in /api.

C

Codex App

Install the plugin from the repository.

git clone https://github.com/jurislm/woodpecker-ci-plugin.git
cd woodpecker-ci-plugin
codex plugin marketplace add .
codex plugin add woodpecker-ci@woodpecker-ci-marketplace

Set WOODPECKER_URL and WOODPECKER_API_TOKEN in the MCP server process environment. The macOS Codex app does not inherit interactive shell settings; see the full setup guide below.

↗

Cursor

Import the plugin from GitHub.

  1. Open Customize → Add Marketplace → Import from GitHub.
  2. Enter jurislm/woodpecker-ci-plugin and add Woodpecker CI Plugin.
  3. Set the Woodpecker URL and token in the plugin configuration.
Open the repository ↗
Use a direct MCP configuration

For other MCP hosts, run the published package with bunx and set credentials in the MCP server environment. Do not commit credential values.

{
  "mcpServers": {
    "woodpecker-ci": {
      "command": "bunx",
      "args": ["-y", "@jurislm/woodpecker-ci-plugin@latest"],
      "env": {
        "WOODPECKER_URL": "https://ci.example.com/api",
        "WOODPECKER_API_TOKEN": "..."
      }
    }
  }
}

SECURITY & LIMITS

Configure credentials in your MCP server environment.

The server sends the token to your configured Woodpecker API as a Bearer token. It does not log the token or include it in MCP tool request metadata. Recognized credential fields in structured JSON responses are replaced with [REDACTED]. Keep credentials out of checked-in files.

  • 01 No hosted HTTPS /mcp endpoint
  • 02 No OAuth flow
  • 03 DRONE_TOKEN is not used
